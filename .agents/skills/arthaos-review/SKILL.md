# ArthaOS review

Remain read-only unless the user also asks for fixes. Select the applicable docs and operational workflows; do not load unrelated material. Treat code, migrations, and tests as stronger implementation evidence than target documents.

For each finding, report severity, exact path, evidence, impact, and a reproducible check. Do not make unsupported compliance, correctness, browser, or production-readiness claims. Current-law claims require authoritative current sources.

Run relevant backend, frontend, documentation, repository-policy, and assumption-freshness checks. Report failures, warnings, skipped checks, and environment limitations separately. A stale financial assumption is a failure, not a warning.

When delegation is authorized, assign independent bounded reviews by concern and reconcile their evidence rather than copying conclusions uncritically.
